# Windows processes


**Windows processes by Zabbix agent.yaml** - Шаблон мониторинга процессов Windows: контроль максимального и минимального количества работающих процессов + получение метрик производительности в контексте процесса.

На уровне шаблона созданы 4 макроса:
- `{$PROC.MAX.COUNT}=Значение не задано`

    Максимальное количество работающих процессов (целое число). На уровне шаблона значение не задано и, соответственно, максимальное количество работающих процессов не контролируется. При необходимости контроля необходимо переопределение этого макроса на уровне хоста в контексте процесса!
- `{$PROC.MIN.COUNT}=1`

    Минимальное количество работающих процессов (целое число).
- `{$PROC.NAME.MATCHES}=Значение не задано`

    Регулярное выражение для описания имён процессов, которые необходимо обнаруживать правилами низкоуровневого 
    обнаружения. На уровне шаблона значение не задано в целях безопасности.
- `{$PROC.NAME.NOT_MATCHES}=Значение не задано`

    Регулярное выражение для описания имён процессов, которые НЕ ТРЕБУЕТСЯ обнаруживать правилами низкоуровневого обнаружения. На уровне шаблона значение не задано в целях безопасности.

При присоединении шаблона к хосту Windows правила обнаружения процессов работать не будут, т.к. значение 
макроса `{$PROC.NAME.MATCHES}` не задано.

Для активизации процесса обнаружения интересующих процессов (например: `cmd.exe, MS Outlook, zabbix-agent, Яндекс-браузер`) необходимо на этом хосте создать макрос `{$PROC.NAME.MATCHES}`, равный по значению регулярному выражению, описывающему имена процессов указанных в примере.

Например: `{$PROC.NAME.MATCHES}=^cmd.+|OUTLOOK.+|zabbix.+|browser.+$`

(Для успешного обнаружения процессов необходимо, чтобы они были запущены.)

В такой конфигурации: 
- триггер контроля минимального количества запущенных экземпляров процесса будет срабатывать
при условии уменьшения их количества до нуля (макрос `{$PROC.MIN.COUNT}=1)`;
- триггер контроля максимального количества запущенных экземпляров процесса срабатывать не будет
(макрос `{$PROC.MAX.COUNT}=Значение не задано`)

В случае необходимости изменения логики работы триггеров контроля минимального и максимального количества экземпляров запущенного процесса, необходимо создать на хосте два контекстных макроса, где контекстом будет являться имя процесса

(пример с `cmd.exe`):

`{$PROC.MAX.COUNT:"cmd.exe"}=6`

`{$PROC.MIN.COUNT:"cmd.exe"}=3`

т.е. в такой конфигурации триггер контроля количества запущенных экземпляров процесса `cmd.exe` будет срабатывать в случае выхода значения количества запущенных экземпляров процесса `cmd.exe` за обе границы интервала (3-6) процессов.

В шаблоне выключено отключение более необнаруживаемых процессов. Удаление более необнаруживаемых процессов произойдёт через 7 дней.
